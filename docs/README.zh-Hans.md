# DSH Bezel

[English](../README.md) · **简体中文** · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Español](README.es.md)

一个原生 macOS 外壳，把 dsh Host 自己的 Web UI 直接装进 `WKWebView`，然后在显示之外只补一个外壳能正当补的东西：**选择连哪个 dsh**、**知道显示正在叫你**、以及**自己的界面语言**。

完整的工程设计——线上契约、决策规则、状态模型、源码地图——都在 [architecture.md](../architecture.md)（仅英文）。本 README 只保留设计的形状、用法，以及与其它工具的比较。

## 设计概要

四个决定定义了整个应用：

- **页面即应用。** 一个 `WKWebView` 加载 Host 自己的 Web UI——纯显示，零注入，零读回。dsh 界面的每一项功能都自动跟随 Host 版本，因为本应用既不改动页面、也不解读页面。
- **通知来自 Host API，而非页面。** 一条独立、便宜的通道——`HostFeed`——持有一条经 Cookie 授权的 WebSocket，并偶尔拉取会话列表。结束是一个 `running` 标志落下；召唤是一次被动旁听的瀑布事件，答题的垄断权仍归显示中的页面。
- **显示会自新。** 页面挂上几天，渲染器内存就会越堆越多，所以应用会在页面满一天后重载它——但只在没有任何窗口可见时，绝不在 Host 等待回答时。
- **一个 JSON 文件记住一切**，原子写入、宽容解码；托管的 `dsh` 子程序经由用户真实的 shell 环境找到，产生，并在退出时终止。

这几条各自具体意味着什么、为什么长成这样，是 [architecture.md](../architecture.md)（仅英文）的主题。

## 快速开始

```sh
swift build --disable-sandbox   # 编译（这个标志只在 DSH harness 下需要）
swift test --disable-sandbox    # 连接模型、通知线上格式、配置文件的单元测试
./scripts/make-app.sh           # 产出 build/DSH Bezel.app
open "build/DSH Bezel.app"
```

`swift run dsh-bezel` 也行，但那是裸可执行文件：没有 bundle，`Info.plist` 里的 ATS 例外不生效，Cookie 与偏好的归属不稳定，macOS 也不会投递通知。正经使用请用 `.app`。

## 首次启动引导

首次启动打开的是一段简短的引导，而不是主窗口。它会侦测是否已有 DSH 程序在伺服 Web UI，并据此给出选项：

- **绑定现有程序**——把本应用指向一个你自己启动的 `dsh`，贴上它启动输出里的位址和 token。
- **代管启动一个新的**——本应用运行子程序，退出时终止它。*自动*会寻找已安装的 `dsh`（找不到时提供经 npm 安装，那需要 Node.js）；*手动*执行你提供的启动命令，只要它打印 `dsh web: http://…` 启动行。

跳过引导会落在连线提示上，一步之遥；引导只在配置文件被删除后才会回来。

## 界面语言

界面默认英语，与 macOS 自身的语言设置无关。设置窗口 →「通用」→「语言」可切换为简体中文、繁體中文、日本語、Français、Deutsch 或 Español，选择写进下面那个配置文件，重启后保持。

唯一不能在会话中切换的是原生菜单栏：macOS 在启动时按 bundle 的本地化绘制它。每次启动，应用会在构建 UI 之前把配置的语言镜像进 `AppleLanguages`，且 bundle 为每种支持的语言都带了 `.lproj`，于是菜单栏在下次启动时跟随设置。所选语言和菜单栏不一致时，设置里就为此给出一个重启按钮。

这项设置只覆盖本应用自己的界面。Host 的 Web UI 由 Host 伺服，语言由它自己决定。

## 设置

设置窗口（工具栏 Host 菜单 →「管理 Host…」，或 ⌘,）有两个标签页。

**Host**——增删改书签：

| 字段 | 含义 |
| --- | --- |
| 名称 | 显示在选择器里；留空则用位址 |
| 位址 | Host 的 origin，例如 `http://127.0.0.1:3080` |
| 启动 token | `dsh web` 输出里的 `?token=…`；仅在没有 Cookie 时需要 |
| 由本应用启动本地 dsh | 本应用产生子程序 |
| profile | 托管模式的 `--profile`，默认 `web` |
| 额外参数 | 追加到 `dsh` 调用后，例如 `--trusted-host dsh.internal` |
| 自定义启动命令 | 托管模式下整体替换调用；必须打印 `dsh web: http://…` 行 |
| dsh 可执行文件路径 | 托管模式运行哪个 `dsh`；留空表示搜索 |

**通用**——属于应用而非某个 Host 的偏好：

| 字段 | 含义 |
| --- | --- |
| 语言 | 界面语言：英语（默认）、简体中文、繁體中文、日本語、Français、Deutsch 或 Español |
| 通知 | 等待中的 Host 与结束的任务的 macOS 通知；默认开启 |
| 自动刷新页面 | 页面在后台满一天后自动重新加载，默认开启 |
| 配置文件 | 配置存于何处；显示路径，选中可以拷贝 |

书签与其余配置随编辑写入那个文件；写入、迁移与保护的方式见 [architecture.md](../architecture.md) 的 "What is remembered" 一节。

## 与其它工具的比较

凡是把 dsh Web UI 装进窗口的工具，无非三种形态：直接用浏览器标签页打开 Host 自己的页面、套在页面外面的通用"套壳"应用、以及重实现线上协议的原生客户端。

| | 浏览器标签页打开 `dsh web` | 通用"套壳"应用 | DSH Bezel | 重实现协议的原生客户端 |
| --- | --- | --- | --- | --- |
| 交互 | Host 的 Web UI | Host 的 Web UI | 同一个 Host Web UI，在 WebKit 视图里——零协议漂移 | 原生重实现的界面 |
| 需要维护的协议 | 无 | 无 | 交互无需维护；通知有一小块被测试钉住的切片 | 整个线上协议 |
| macOS 通知 | 无 | 无 | 有——等待与结束，任何会话 | 有 |
| 书签、托管子程序、首次启动引导 | 无 | 无 | 有 | 有 |
| 界面语言 | Host 自己的 | 它自己的 | 七种，含菜单栏 | 它自己的 |
| 页面之外的内存 | 无 | 自带的第二个浏览器引擎 | 一个套接字 | 原生界面 |

- **对比普通浏览器标签页**：页面一模一样——本应用从不改进它。外壳补的东西全部在页面之外：书签与托管子程序，让打开应用就够了；通知，让等待中的 Host 不被错过；自新，让挂上几周的显示保持健康；还有语言处理。
- **对比通用"套壳"应用**：它们自带一个浏览器引擎——为了把同一个页面装进一个打扮过的窗口，付出整个第二运行时的内存——而且对被包裹的东西一无所知。本应用用系统 WebKit，页面花多少内存就是页面本身的成本，而外壳理解它的 Host：怎么找到、启动、盯住、重连。
- **对比重实现协议的原生客户端**：完全原生的交互是奖赏，代价是自己追踪线上协议、自己扛漂移。本项目在交互上刻意不这么做。你点击、键入、读到的每一样东西，都是 Host 自己的 Web UI，本应用对它一概不理解。唯一的例外是通知：`HostFeed` 订阅同一个 API 的一小块——会话列表、一个状态事件、两道召唤门——因为从页面学这些，意味着往页面里注入脚本、并为第二个渲染器买单。这一小块正好就是 `HostFeedWire`：纯解析函数，由从真实 Host 录制的测试钉住，漂移因此落在一个可测试的地方。这些形态可以并存；本应用确实补的原生形状的东西——通知、跟随语言的菜单栏——都包在页面外面，不碰你驱动页面的方式。
- **放弃了什么**：结束通知不再引用你自己的原话（改由会话标题指名任务）；通知线上格式跟随 Host 版本——但只在那块被测试钉住的小表面之内。
- **前置条件**：一个能伺服 Web UI 的 dsh Host（自 0.1.5-rc.1 起稳定）。要用域名连远程 Host，那个 Host 必须带 `--trusted-host` 启动——dsh 的 `/api` 有一道浏览器信任栏；其余见 [architecture.md](../architecture.md) 的 "Known constraints"。

## 开发

```sh
swift build --disable-sandbox
swift test --disable-sandbox
swift run dsh-bezel --dump-config   # 配置文件：路径，或它装着什么
swift run dsh-bezel --dump-hosts    # 只看保存的书签
swift run dsh-bezel --watch-feed "http://127.0.0.1:PORT/?token=…"
                                    # 把通知通道接到一个 Host 上，
                                    # 打印它学到的每一条事实——线上
                                    # 契约，实时
```

裸可执行文件和 bundle 共用一个配置文件，所以 `swift run` 做实验用的就是真实配置——除非 `BEZEL_CONFIG` 另有指向。在 DSH harness 下构建需要 `--disable-sandbox`，因为它嵌不进自己的沙箱。
