# DSH Bezel

[English](../README.md) · [简体中文](README.zh-Hans.md) · **繁體中文** · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Español](README.es.md)

一個原生 macOS 外殼，把 dsh Host 自己的 Web UI 直接裝進 `WKWebView`，然後在顯示之外只補一個外殼能正當補的東西：**選擇連哪個 dsh**、**知道顯示正在叫你**、以及**自己的介面語言**。

完整的工程設計——線上契約、決策規則、狀態模型、原始碼布局——住在 [architecture.md](../architecture.md) 裡（僅英文）。這份 README 保留設計的形狀、應用程式的用法，以及它與替代方案的比較。

## 設計概要

四個決定定義了整個應用程式：

- **頁面就是應用程式。** 一個 `WKWebView` 載入 Host 自己的 Web UI——純粹的顯示，零注入，零讀回。dsh 介面的每個功能都自動跟隨 Host 版本，因為本應用程式既不改動頁面，也不解讀頁面。
- **通知來自 Host API，不來自頁面。** 一條獨立、便宜的通道——`HostFeed`——持有一條以 Cookie 授權的 WebSocket，偶爾拉取對話清單。結束，是 `running` 旗標落下；召喚，是一個被動旁聽的瀑布事件，而顯示中的頁面繼續壟斷回答。
- **顯示自己會自新。** 頁面一掛幾天，渲染記憶體只會一路堆積，所以應用程式在頁面滿一天後重新載入它——但只在沒有視窗可見時動手，Host 等一個答覆時絕不。
- **一個 JSON 檔案記住一切**，原子寫入、寬容解碼；代管的 `dsh` 子程序透過使用者的真實 shell 環境找到，由應用程式產生，結束時終止。

這四條各自意味著什麼、為什麼塑成這樣，是 [architecture.md](../architecture.md) 的主題。

## 快速開始

```sh
swift build --disable-sandbox   # 編譯（這個旗標只在 DSH harness 下需要）
swift test --disable-sandbox    # 連接模型、通知線上格式、設定檔的單元測試
./scripts/make-app.sh           # 產出 build/DSH Bezel.app
open "build/DSH Bezel.app"
```

`swift run dsh-bezel` 也行，但那是裸可執行檔：沒有 bundle，`Info.plist` 裡的 ATS 例外不生效，Cookie 與偏好的歸屬不穩定，macOS 也不會投遞通知。正經使用請用 `.app`。

## 首次啟動引導

首次啟動開啟的是一段簡短的引導，而不是主視窗。它會偵測是否已有 DSH 程序在伺服 Web UI，並據此給出選項：

- **綁定現有程序**——把本應用程式指向一個你自己啟動的 `dsh`，貼上它啟動輸出裡的位址和 token。
- **代管啟動一個新的**——本應用程式執行子程序，結束時終止它。*自動*會尋找已安裝的 `dsh`（找不到時提供經 npm 安裝，那需要 Node.js）；*手動*執行你提供的啟動命令，只要它列印 `dsh web: http://…` 啟動行。

略過引導會落在連線提示上，一步之遙；引導只在設定檔被刪除後才會回來。

## 介面語言

介面預設英語，與 macOS 自身的語言設定無關。設定視窗 →「一般」→「語言」可切換為簡體中文、繁體中文、日本語、Français、Deutsch 或 Español，選擇寫進下面那個設定檔，重新啟動後保持。

唯一不能在作業階段中切換的是原生選單列：macOS 在啟動時按 bundle 的在地化繪製它。每次啟動，應用程式會在建構 UI 之前把設定的語言鏡射進 `AppleLanguages`，且 bundle 為每種支援的語言都帶了 `.lproj`，於是選單列在下次啟動時跟隨設定。所選語言和選單列不一致時，設定裡就為此給出一個重新啟動按鈕。

這項設定只涵蓋本應用程式自己的介面。Host 的 Web UI 由 Host 伺服，語言由它自己決定。

## 設定

設定視窗（工具列 Host 選單 →「管理 Host…」，或 ⌘,）有兩個標籤頁。

**Host**——增刪改書籤：

| 欄位 | 含義 |
| --- | --- |
| 名稱 | 顯示在選擇器裡；留空則用位址 |
| 位址 | Host 的 origin，例如 `http://127.0.0.1:3080` |
| 啟動 token | `dsh web` 輸出裡的 `?token=…`；僅在沒有 Cookie 時需要 |
| 由本應用程式啟動本機 dsh | 本應用程式產生子程序 |
| profile | 代管模式的 `--profile`，預設 `web` |
| 額外參數 | 追加到 `dsh` 呼叫後，例如 `--trusted-host dsh.internal` |
| 自訂啟動命令 | 代管模式下整體替換呼叫；必須列印 `dsh web: http://…` 行 |
| dsh 可執行檔路徑 | 代管模式執行哪個 `dsh`；留空表示搜尋 |

**一般**——屬於應用程式而非某個 Host 的偏好：

| 欄位 | 含義 |
| --- | --- |
| 語言 | 介面語言：英語（預設）、簡體中文、繁體中文、日本語、Français、Deutsch 或 Español |
| 通知 | 等待中的 Host 與結束的任務的 macOS 通知；預設開啟 |
| 自動重新整理頁面 | 頁面在背景滿一天後自動重新載入，預設開啟 |
| 設定檔 | 設定存於何處；顯示路徑，選取可以拷貝 |

書籤與其餘設定隨編輯寫入那個檔案；寫入、遷移與保護的方式，見 [architecture.md](../architecture.md) 的「What is remembered」一節。

## 與其它工具的比較

凡是把 dsh Web UI 裝進視窗的工具，無非三種形態：直接用瀏覽器分頁打開 Host 自己的頁面、套在頁面外面的通用「套殼」應用、以及重實作線上協定的原生用戶端。

| | `dsh web` 的瀏覽器分頁 | 通用「套殼」應用 | DSH Bezel | 重實作協定的原生用戶端 |
| --- | --- | --- | --- | --- |
| 互動 | Host 的 Web UI | Host 的 Web UI | 同一個 Host Web UI，裝在 WebKit 檢視裡——零協定漂移 | 介面的原生重實作 |
| 需要維護的協定 | 無 | 無 | 互動上無；通知上是一小片由測試釘住的面 | 整套線上協定 |
| macOS 通知 | 無 | 無 | 有——等待與結束，任何對話都算 | 有 |
| 書籤、代管子程序、首次啟動引導 | 無 | 無 | 有 | 有 |
| 介面語言 | Host 自己的 | 自己的 | 七種，選單列也在內 | 自己的 |
| 頁面之外的記憶體 | 無 | 自帶的第二個瀏覽器引擎 | 一個 socket | 原生介面 |

- **對比瀏覽器分頁**：頁面一模一樣——本應用程式從不改良它。外殼補的東西全在頁面之外：書籤與代管子程序，讓開啟應用程式就足夠；通知，讓等待中的 Host 不會被錯過；自新，讓一掛幾星期的顯示保持健康；以及語言處理。
- **對比通用「套殼」應用**：它們自帶一個瀏覽器引擎——為了把同一個頁面裝進一個打扮過的視窗，付出整個第二執行環境的記憶體——而且對被包裹的東西一無所知。本應用程式用系統 WebKit，頁面花多少記憶體就是頁面本身的成本，而外殼理解它的 Host：怎麼找到、啟動、盯住、重連。
- **對比重實作協定的原生用戶端**：它走另一條路——用 Swift 重實作線上協定（一元 RPC + `/api/remote.mux` + 事件串流），換來完全原生的互動，代價是自己追蹤協定、自己扛漂移。本專案刻意不這麼做——在互動上。你點的、打的、讀的一切，都是 Host 自己的 Web UI，本應用程式對其一無所解。唯一的例外是通知：`HostFeed` 訂閱同一個 API 的一小片——對話清單、一個狀態事件、兩道召喚閘——因為要從頁面上學這些，就得往頁面注入指令碼，並為第二個渲染器付帳。這一小片恰好就是 `HostFeedWire`——純解析函式，由從真實 Host 錄下的測試釘住。兩者可以並存；本應用程式確實補的原生形狀的東西——通知、跟隨語言的選單列——都包在頁面外面，不碰你驅動頁面的方式。
- **放棄了什麼**：任務結束的通知不再引用你自己的原話（改由對話標題指名這個任務），而且通知的線上格式在那一小片由測試釘住的面上跟隨 Host 版本。
- **前置條件**：一個能伺服 Web UI 的 dsh Host（自 0.1.5-rc.1 起穩定）。要用網域名稱連遠端 Host，那個 Host 必須帶 `--trusted-host` 啟動——dsh 的 `/api` 有一道瀏覽器信任欄；其餘的見 [architecture.md](../architecture.md) 的「Known constraints」一節。

## 開發

```sh
swift build --disable-sandbox
swift test --disable-sandbox
swift run dsh-bezel --dump-config   # 設定檔：路徑，或它裝著什麼
swift run dsh-bezel --dump-hosts    # 只看儲存的書籤
swift run dsh-bezel --watch-feed "http://127.0.0.1:PORT/?token=…"
                                    # 把通知通道接到一個 Host 上，
                                    # 列印它學到的每一條事實——
                                    # 線上契約，活的
```

裸可執行檔和 bundle 共用一個設定檔，所以 `swift run` 做實驗用的就是真實設定——除非 `BEZEL_CONFIG` 另有指向。在 DSH harness 下建置需要 `--disable-sandbox`，因為它嵌不進自己的沙箱。
