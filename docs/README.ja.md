# DSH Bezel

[English](../README.md) · [简体中文](README.zh-Hans.md) · [繁體中文](README.zh-Hant.md) · **日本語** · [Français](README.fr.md) · [Deutsch](README.de.md) · [Español](README.es.md)

dsh Host 自身の Web UI をそのまま `WKWebView` に読み込むネイティブな macOS シェルで、ディスプレイの周りに正当に足せるものだけを足します：**どの dsh に接続するかの選択**、**ディスプレイがあなたを呼んでいると知ること**、そして**アプリ自身のインターフェイス言語**。

エンジニアリング設計の全体——回線の契約、判断のルール、状態モデル、ソースマップ——は [architecture.md](../architecture.md)（英語のみ）にあります。この README は設計の形、アプリの使い方、そして他の選択肢との比較を保ちます。

## 設計の概要

アプリ全体を定めるのは 4 つの決定です：

- **ページこそがアプリ。** 1 つの `WKWebView` が Host 自身の Web UI を読み込みます——純粋な表示、注入ゼロ、読み戻しゼロ。dsh のインターフェイスのすべての機能は、このアプリがページを変更せず解釈もしないため、Host のバージョンに自動で追従します。
- **通知はページではなく Host API から。** 別の、安価なチャネル——`HostFeed`——が Cookie 認証の WebSocket を 1 本保持し、時々セッションリストを取得します。完了とは `running` フラグが下がること、召喚とは受動的に聞かれるウォーターフォールイベントのことです。答えを返す独占は、表示中のページが保ちます。
- **表示は自ら更新される。** ページを何日も出しっ放しにするとレンダラーのメモリが積み上がるため、アプリは読み込みから 1 日経過したページを再読み込みします——ただしウインドウが 1 つも見えていないときだけ、そして Host が答えを待っているあいだは決して。
- **1 つの JSON ファイルがすべてを覚え**、アトミックに書き込まれ、寛容にデコードされます。代行起動される `dsh` の子プロセスは、ユーザーの実際のシェル環境から見つけられ、生成され、終了時に停止されます。

それぞれが詳しく何を意味し、なぜその形をしているのかは、[architecture.md](../architecture.md) の主題です。

## クイックスタート

```sh
swift build --disable-sandbox   # コンパイル（このフラグは DSH harness 配下でのみ必要）
swift test --disable-sandbox    # 接続モデル、通知ワイヤ形式、設定ファイルの単体テスト
./scripts/make-app.sh           # build/DSH Bezel.app を生成
open "build/DSH Bezel.app"
```

`swift run dsh-bezel` も動きますが、それは裸の実行ファイルです。bundle がないため `Info.plist` の ATS 例外が適用されず、Cookie と設定の所有が不安定で、macOS は通知を配達しません。実用には `.app` を使ってください。

## 初回起動ガイド

初回起動ではメインウインドウではなく、短いガイドが開きます。すでに DSH プロセスが Web UI をサーブしているかを検出し、その結果に応じて選択肢を出します：

- **実行中のプロセスにバインド**——自分で起動した `dsh` にこのアプリを向かせます。起動出力のアドレスと token を貼り付けるだけです。
- **代行起動する**——このアプリが子プロセスを実行し、終了時に停止します。*自動* はインストール済みの `dsh` を探し（見つからなければ npm でのインストールを提案します。Node.js が必要です）、*手動* は `dsh web: http://…` 起動行を出力するコマンドをあなたが指定して実行します。

ガイドをスキップすれば接続プロンプトに落ちます。ガイドが戻ってくるのは設定ファイルが削除されたときだけです。

## インターフェイス言語

インターフェイスはデフォルトで英語です。macOS 自身の言語設定には依存しません。設定 →「一般」→「言語」で 简体中文、繁體中文、日本語、Français、Deutsch、Español に切り替えられます。選択は下で述べる設定ファイルに書き込まれるため、再起動後も保持されます。

セッション途中で切り替えられない唯一の部分はネイティブのメニューバーです。macOS は起動時に bundle のローカライズからそれを描画します。このアプリは毎回の起動時に、UI を構築する前に設定された言語を `AppleLanguages` へミラーし、bundle はサポートする各言語の `.lproj` を同梱しているため、メニューは次回起動時に設定へ追従します。選択中の言語とメニューバーの言語が不一致のあいだ、設定にはまさにそのための再起動ボタンが表示されます。

この設定がカバーするのはこのアプリ自身のインターフェイスだけです。Host の Web UI は Host がサーブするもので、言語設定も Host 自身のものです。

## 設定

設定ウインドウ（ツールバーの Host メニュー →「Host を管理…」、または ⌘,）には 2 つのタブがあります。

**Host**——ブックマークの追加・削除・編集：

| フィールド | 意味 |
| --- | --- |
| 名前 | ピッカーに表示される。空の場合はアドレスが使われる |
| アドレス | Host の origin。例：`http://127.0.0.1:3080` |
| 起動 token | `dsh web` の出力の `?token=…`。Cookie を保持していないあいだだけ必要 |
| この Host のローカル dsh を起動 | アプリが子プロセスを生成する |
| profile | 代行起動モードの `--profile`。デフォルトは `web` |
| 追加引数 | `dsh` の呼び出しに追加される。例：`--trusted-host dsh.internal` |
| カスタム起動コマンド | 代行起動モードで呼び出し全体を置き換える。`dsh web: http://…` 行を出力する必要がある |
| dsh 実行ファイルパス | 代行起動モードでどの `dsh` を実行するか。空なら検索 |

**一般**——特定の Host ではなくアプリ自身に属する設定：

| フィールド | 意味 |
| --- | --- |
| 言語 | インターフェイス言語：英語（デフォルト）、简体中文、繁體中文、日本語、Français、Deutsch、Español |
| 通知 | 待機中の Host と終了したタスクの macOS 通知。デフォルトで有効 |
| ページの自動再読み込み | ページをバックグラウンドで 1 日表示したあと、自動で再読み込みする。デフォルトで有効 |
| 設定ファイル | 設定がどこに保存されるか。パスが表示され、選択してコピーできる |

ブックマークとその他の設定は、編集するとそのファイルに書き込まれます。書き込み・移行・保護のされ方は、[architecture.md](../architecture.md) の "What is remembered" を参照してください。

## 他のツールとの比較

dsh の Web UI をウインドウに収めるツールは、三つの形のどれかです：Host 自身のページをブラウザタブで開くか、ページを包む汎用ラッパーアプリか、通信プロトコルを再実装するネイティブクライアントか。

| | `dsh web` のブラウザタブ | 汎用ラッパーアプリ | DSH Bezel | プロトコルを再実装するネイティブクライアント |
| --- | --- | --- | --- | --- |
| インタラクション | Host の Web UI | Host の Web UI | 同じ Host の Web UI を WebKit ビューで——プロトコルドリフトゼロ | インターフェイスのネイティブな再実装 |
| 維持すべきプロトコル | なし | なし | インタラクションについてはなし。通知については、テストで固定された狭いスライス | 回線プロトコル全体 |
| macOS 通知 | なし | なし | あり——任意のセッションの待機と完了 | あり |
| ブックマーク・管理子プロセス・初回起動ガイド | なし | なし | あり | あり |
| インターフェイス言語 | Host 自身のもの | 独自のもの | 7 つ（メニューバーを含む） | 独自のもの |
| ページ以外のメモリ | なし | 同梱された第二のブラウザエンジン | ソケット 1 本 | ネイティブなインターフェイス |

- **通常のブラウザタブとの比較**：ページは同一です——このアプリはそれを決して改善しません。シェルが足すものはすべて、その周りにあります。アプリを開くだけで済むブックマークと代行起動の子、待機中の Host を見逃さないための通知、何週間も出しっ放しのディスプレイを健康に保つ更新、そして言語の処理です。
- **汎用ラッパーとの比較**：独自のブラウザエンジンを同梱し——同じページを飾り立てたウインドウで見せるために、丸ごと第二のランタイムのメモリを払う——そして包んでいるものが何かを知りません。このアプリはシステムの WebKit を使うので、ページのコストはページ自身の分だけで済み、シェルは Host を理解しています：見つけ方、起動、監視、再接続。
- **ネイティブ再実装との比較**：もう一方の道を行きます。通信プロトコルを Swift で再実装する（単項 RPC + `/api/remote.mux` + イベントストリーム）道です。完全にネイティブなインタラクションが得られる代わりに、プロトコルを自分で追跡し、ドリフトを自分で背負います。このプロジェクトは意図的にそれをしません——インタラクションについては。クリックするもの、タイプするもの、読むものはすべて Host 自身の Web UI であり、アプリはそれを何ひとつ理解しません。唯一の例外が通知です。`HostFeed` は同じ API の狭いスライス——セッションリスト、1 つのステータスイベント、2 つの召喚ゲート——を購読します。これらをページから学ぶということは、ページにスクリプトを注入し、2 つ目のレンダラーの代償を払うことだったからです。そのスライスはまさに `HostFeedWire` で、実 Host から記録したテストで固定された純粋なパース関数なので、ドリフトは 1 つのテスト可能な場所に落ちます。両者は共存できます。このアプリが足すネイティブな形のもの——通知、言語に追従するメニューバー——は、あなたがページを操るやり方に触れず、ページを包むだけです。
- **失うもの**：完了通知はもはやユーザー自身のプロンプトを引用しません（代わりにセッションタイトルがタスクを名指しします）。そして通知の回線形式は、その小さなテストで固定された表面の中で Host のバージョンに追従します。
- **前提条件**：Web UI をサーブできる dsh Host（0.1.5-rc.1 から安定）。ドメイン名で到達するリモート Host は `--trusted-host` 付きで起動する必要があります——dsh の `/api` にはブラウザ信頼の垣根があります。そのほかは [architecture.md](../architecture.md) の "Known constraints" を参照してください。

## 開発

```sh
swift build --disable-sandbox
swift test --disable-sandbox
swift run dsh-bezel --dump-config   # 設定ファイル：そのパス、または中身
swift run dsh-bezel --dump-hosts    # 保存されたブックマークだけ
swift run dsh-bezel --watch-feed "http://127.0.0.1:PORT/?token=…"
                                    # 通知チャネルを Host に接続して、
                                    # 学んだすべての事実を表示する——
                                    # 回線の契約、ライブで
```

裸の実行ファイルと bundle は 1 つの設定ファイルを共有するため、`swift run` での実験は実際の設定を使います——`BEZEL_CONFIG` が別を指していない限り。DSH harness 配下でのビルドには `--disable-sandbox` が必要です。harness は自身のサンドボックスを入れ子にできないからです。
