# DSH Bezel

[English](../README.md) · [简体中文](README.zh-Hans.md) · [繁體中文](README.zh-Hant.md) · **日本語** · [Français](README.fr.md) · [Deutsch](README.de.md) · [Español](README.es.md)

yet-another-dsh-for-mac。dsh Host 自身の Web UI をそのまま `WKWebView` に読み込むネイティブな macOS シェルで、ディスプレイの周りに正当に足せるものだけを足します：**どの dsh に接続するかの選択**、**ディスプレイがあなたを呼んでいると知ること**、そして**アプリ自身のインターフェイス言語**。

## なぜプロトコル再実装ではなくシェルなのか

dsh の Web UI はアプリに同梱できる静的フロントエンドではありません。Host 自身がサーブする完全なアプリケーションです：

- SPA は Host の frontend-static シートからサーブされる；
- 各 `dsh.client` プラグインのブラウザバンドルは `/plugins/<id>/client.js` からサーブされる；
- `window.__DSH_BOOT__` ブートストラップペイロードは、インデックスがレンダリングされるたびに Host から注入される。

つまり「どの dsh に接続するか」は実装上「`WKWebView` がどの URL を読み込むか」に帰着します。これが買うものは**プロトコルドリフトゼロ**です。セッションのレンダリング、承認、計画、ゴール、ツールカード、添付、設定、モデル選択、サードパーティ製ブラウザプラグインがすべて Host のバージョンに自動で追従します。このプロジェクトは `/api` も `/api/remote.mux` もイベント型も理解する必要が永遠にありません。

## クイックスタート

```sh
swift build --disable-sandbox   # コンパイル（このフラグは DSH harness 配下でのみ必要）
swift test --disable-sandbox    # 接続モデルとページシグナルの単体テスト
./scripts/make-app.sh           # build/DSH Bezel.app を生成
open "build/DSH Bezel.app"
```

`swift run dsh-bezel` も動きますが、それは裸の実行ファイルです。bundle がないため `Info.plist` の ATS 例外が適用されず、Cookie と設定の所有が不安定で、macOS は通知を配達しません。実用には `.app` を使ってください。

## 初回起動ガイド

初回起動ではメインウインドウではなく、短いガイドが開きます。すでに DSH プロセスが Web UI をサーブしているかを検出し、その結果に応じて選択肢を出します：

- **実行中のプロセスにバインド**——自分で起動した `dsh` にこのアプリを向かせます。起動出力のアドレスと token を貼り付けるだけです。
- **代行起動する**——このアプリが子プロセスを実行し、終了時に停止します。*自動* はインストール済みの `dsh` を探し（見つからなければ npm でのインストールを提案します。Node.js が必要です）、*手動* は `dsh web: http://…` 起動行を出力するコマンドをあなたが指定して実行します。

ガイドをスキップすれば接続プロンプトに落ちます。ガイドが戻ってくるのは設定ファイルが削除されたときだけです。

## インターフェイス言語

インターフェイスはデフォルトで英語です。macOS 自身の言語設定には依存しません。設定 →「一般」→「言語」で 简体中文、繁體中文、日本語、Français、Deutsch、Español に切り替えられます。選択は下で述べる設定ファイルに書き込まれるため、再起動後も保持されます。

7 つの言語はすべて 1 つのファイルに網羅 switch で住んでいます。したがってメッセージが一部の言語だけで出荷されることはありません。翻訳の漏れはビルドを失敗させます。英語 UI に紛れ込んだ中国語の文字列、ということが起きないようにです。このファイルは実行時診断の文言も保持しています。診断は構造化値として運ばれ、表示時にレンダリングされるため、言語を切り替えると、すでに画面にある失敗メッセージも新しい言語で描き直されます。

セッション途中で切り替えられない唯一の部分はネイティブのメニューバーです。macOS は起動時に bundle のローカライズからそれを描画します。このアプリは毎回の起動時に、UI を構築する前に設定された言語を `AppleLanguages` へミラーし、bundle はサポートする各言語の `.lproj` を同梱しているため、メニューは次回起動時に設定へ追従します。選択中の言語とメニューバーの言語が不一致のあいだ、設定にはまさにそのための再起動ボタンが表示されます。

この設定がカバーするのはこのアプリ自身のインターフェイスだけです。Host の Web UI は Host がサーブするもので、言語設定も Host 自身のものです。

## 通知

ベゼルがディスプレイの周りに正当に足せる唯一の能力は、ディスプレイがあなたを呼んでいると知ることです。呼ぶ価値がある瞬間は 2 つ：Host があなたの決定を待っているとき（ツール承認、質問、計画レビュー）、そして実行中のタスクが終わったとき。以下はすべて**ページ監視**です。このアプリはどちらも、あなたが見ているのと同じページから学びます——Host 自身の Web UI がこれらの状況のためにちょうどレンダリングするものを読むことで。何も傍受せず、回線上の何も読まず、ページの中の何も変更しません。

### ページ監視

**注入。** 小さなオブザーバースクリプト——純粋な JavaScript、読み取り専用——が WebKit ユーザースクリプトとして登録され、`WKWebView` が読み込むすべてのページに同行します。ドキュメント終了時に注入されます。ガードにより、再注入されたスクリプト（リロードはユーザースクリプトを再実行します）がインターバルを積み重ねることはありません。

**ポーリング。** スクリプトは毎秒 1 つのスナップショットを取ります。各パスは数回の `querySelector` 呼び出しです。素朴な `MutationObserver` ではなくポーリングを使うのは、ポーリングは、素朴なオブザーバーの要約なら見逃しうる「変更と変更の間にマウントされ、アンマウントされるパネル」を逃さないからです。

**1 つのスナップショットが読むもの**——Host 自身の Web UI がレンダリングするマーカーだけ：

| シグナル | マーカー | 意味 |
| --- | --- | --- |
| 待機パネル | `data-approval-key` / `data-question-key` / `data-plan-review-key` | Host が承認、質問、計画レビューでブロックされている |
| ターン終了 | 最終回答の下の操作行（コピー、fork、使用量、フィードバック）の `data-turn-tail` | Host 自身の「このターンは終わった」マーク——ターンの `turn/end` イベントが届いた瞬間に公開されるため、「タスク終了」はページとまったく同じ意味を持ち、「ストリーミングマーカーが静かになった」からの推測ではない |
| タスク名 | その行が持つターン番号が、そのターンを開始したユーザーメッセージを特定する | 通知は**どのタスクが**終わったかを——あなた自身の言葉で——伝える |
| まだ同じ会話か | 最新のコンテンツ行の `data-chat-anchor-key` | 切り替えはすべての行を置き換えるが、終了したターンはその下に 1 行を足すだけ——会話の切り替えが「終了」と偽装されることはない |
| セッション名 | 選択中のサイドバー行、または `document.title`（`"<セッション> — <製品>"`） | すべての通知がその会話を名指しする |
| バックグラウンドセッション | サイドバー行の `data-state` ドット | 実行中 / 待機中 / 終了済み・未閲覧 |

**スナップショットからイベントへ。** スクリプトは毎秒、スナップショットを専用のブリッジチャンネル（`window.webkit.messageHandlers`）にポストします。アプリはそれをデコードし、純粋で単体テスト済みの検出器が、通知する価値のある遷移を導き出します：注意が現れること、上の行がすべて残っているままのターン終了マークの変化、ステータスドットの反転。ロード後の最初のスナップショットはベースラインにすぎません——現状は状態であってニュースではない——そして、隔たりの後に初めて見えたドットは歴史であってイベントではありません。

### 誰も表示しないバックグラウンド

このページにないタスク——同じ Host のバックグラウンドで動くセッション——は、それらを見せる唯一の表面、サイドバーを通じてカバーされます。サイドバーのセッション行は Host 自身が維持するライブのステータスドット（`data-state`）を持ちます：実行中、あなたを待っている、終了済み・未閲覧。最後のものは Host 自身の「完了リマインダー」で、バックグラウンドセッションが実行からアイドルに転じ、誰もそれを開いていないまさにそのときにセットされます。ドットのエッジが、セッションを名指しする通知になります。

ただしサイドバーは自分のビュー状態が表示するものしかレンダリングしません——折りたたまれたワークスペースグループはセッション行を一切レンダリングせず、展開されたグループも最新 5 件で打ち切られます——したがって表示ページのサイドバーはバックグラウンドの全体ではありません。2 番目の隠し `WKWebView` が同じ Host ページを読み込み（独自の非永続ストア、表示ページの Cookie のコピー、アドレスから一回限りの token を除いたもの）、スキャン前にすべてのグループとオーバーフローを開きます：そのページを見る者はいないので、クリックは自分自身のビュー状態にしか書き込みません。選択を復元しない——何も開かない——ため、Host のクライアントごとの完了ドットはすべてのセッションについてセットされ、プローブがそれを消すことはありません。プローブが生きているあいだ、その行がバックグラウンドの真実です：毎秒 1 回ポストし、15 秒より古い行は表示ページ自身のサイドバーに譲り、30 秒沈黙が続くページは Cookie の新しいコピーとともに再読み込みされます。

### 配達ルール

スナップショットがいつ macOS 通知になるかは、イベントのクラスごとに 2 つのルールに従います。召喚——このページでもバックグラウンドセッションでも、Host が入力や確認を待っていること——は**常に配達されます**。最前面でも、バックグラウンドでも、最小化されていてもです。回答されるまで Host をブロックするからであり、見えているページがすべてのソースをカバーするわけではないからです。完了はステータス報告です。このアプリが最前面でウインドウを立てているあいだは、ページ自身が通知であり、バナーはすでに画面にあるものを繰り返すだけでしょう。通知をクリックするとウインドウが前面に出ます。Dock に最小化されていれば、そこから復元されます。

通知はデフォルトで有効です。設定 →「一般」にスイッチがあり、システムの権限ダイアログは初回起動時に一度だけ尋ねます。macOS が通知を配達するのは app bundle からだけです——`swift run` の裸の実行ファイルは尋ねも通知もしません。

## 覚えていること

アプリが知っているすべては 1 つの JSON ファイルにあります：

```
~/Library/Application Support/dsh-bezel/config.json
```

Host ブックマークとその全設定、ピッカーがどのブックマークにいるか、WebView が最後に接続したのはどれか、そしてインターフェイス言語です。起動時にこのファイルを読み、**最後に接続していた Host に自動再接続します**。アプリを開くだけで前回の場所に戻れます。代行起動の Host は毎回新しく起動されます。ポートと token は毎回新しくなるからです。署名済み `dsh-auth` Cookie は WebKit 自身のデータストアが別に覚えているため、再接続に token はもう要りません。

`UserDefaults` ではなくファイルであるのは、読み、編集し、別のマシンにコピーし、バージョン管理に置けるようにするためです。書き込みは pretty-print・キー整列・スラッシュ非エスケープで行われるので、diff が読みやすいままです。一時ファイルを介したアトミックな書き込みなので、書き込み途中のクラッシュでも切り詰められません。ブックマークに起動 token が入っているかもしれないため、パーミッションは `0600` です。`BEZEL_CONFIG` で別のパスを指せます。

デコードはフィールドごとで、寛容です。未知のキーは無視され、型の合わないスカラーはデフォルトへ落ち、古いビルドが書いたブックマーク（後に追加されたフィールドが欠けているもの）も普通に読み込まれます。まったく解析できないファイルは設定で報告され、**そのまま保存されます**——決して上書きされません。修正すべき誤字を含む手編集も、新しいビルドの書いたファイルも、回復可能なままです。このファイルを削除するのがリセットです。あなたが付けた名前はあなたのデータで、どの言語でもそのまま表示されます。初回に播種されるブックマーク名だけが現在の言語に従います。ウインドウのサイズと位置はこのファイルには含まれません。SwiftUI が自身で覚えます。

## 接続モデル

Host とは、重要なフィールドを 4 つ持つブックマークです：**名前、アドレス（origin）、起動 token（任意）、そしてこのアプリが代行起動するかどうか**。

**外部 Host（代行起動しない）**：`http://host:port` を入力します。その Host がまだこのブラウザに Cookie を渡していないなら、`dsh web` の起動出力の完全なアドレスを「起動 token」に貼るか、`?token=` 付きのアドレスをブラウザで一度開いてからこのアプリに戻ってください（Cookie はこのアプリの WebKit データストア内で、オーソリティごとに共有されます）。

**代行起動 Host**：このアプリは次を実行します：

```sh
dsh --profile web --port 0 --no-open
```

ポート `0` はシステムに選択させ、URL は子プロセスの stdout の `dsh web: http://127.0.0.1:PORT/?token=…` 行から解析します。アプリの終了はその子プロセスを停止します（「切断」ボタンも同様）。30 秒以内にその行が現れない場合は起動タイムアウトと判断して子プロセスを停止するため、インターフェイスが永遠に「起動中」のままになることはありません。

**`dsh` を探す**：Finder でダブルクリックされて起動したアプリは launchd の最小 PATH（`/usr/bin:/bin:/usr/sbin:/sbin`）を継承します。そこには node も npm もありません——実マシンの `dsh` はほぼすべてがインタープリターを必要とするラッパーです（`#!/usr/bin/env node`、`npm exec …`、DSH Desktop のランタイム shim）。「ファイルが存在して x ビットがある」だけでは、利用可能とは言えません。検索はこの順で実行され、候補はそれぞれ `dsh --version` で本当に一度実行されます。成功したものだけが子プロセスに渡されます：

1. Host 設定の「dsh 実行ファイルパス」
2. `BEZEL_DSH_PATH` 環境変数
3. ログインシェルの `command -v dsh`
4. アプリ自身の PATH 上の `dsh`
5. 定番のインストール先：`~/.local/bin`、`~/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、`~/.npm-global/bin`、`~/.bun/bin`、`/opt/anaconda3/bin`、…

ステップ 3 が尋ねるのは**対話的な**ログインシェルです（`zsh -l -i -c`、失敗すれば `-l -c` へ）。`node`/`npm` を置くディレクトリは通常 `~/.zshrc` にあり、非対話の `zsh -l -c` はそれを決して読みません——GUI アプリの PATH とユーザーのターミナルが一致しないのは、まさにこのためです。このプローブは rc ファイルの雑音と答えをセンチネル行で分離し、5 秒のタイムアウトを持ちます。

子プロセスの PATH は、ログインシェルの PATH → アプリが継承した PATH → インタープリターディレクトリ、重複を除いて統合したものです。注入されるのは**インタープリターディレクトリだけ**であることに注意してください——*もうひとつの* `dsh` が住む `~/bin` や `~/.local/bin` のようなディレクトリは決して注入しません。一部のラッパーは自分で PATH を走査して見つけたものに従うため（DSH Desktop の shim がそうです）、別のラッパーを PATH に置くと、起動がそちらに渡され、shim が同梱するランタイムは使われません。

すべての候補が失敗したとき、接続プロンプトは試した各場所と、うまくいかなかった理由（存在しない、または `--version` が動かない）を列挙します。

**資格情報のセマンティクス**：`GET /?token=…` は Host によって 30 日有効な署名済み Cookie（`dsh-auth-<hash(authority)>`、`HttpOnly`）と交換されます。署名鍵は Host の資格情報に永続化されるため、Cookie は Host の再起動を生き延びます。token が必要なのは、Cookie を保持していないあいだだけです。Cookie が有効なあいだ、Host のインデックス承認は任意の `?token=` リクエストをきれいな `/` へ 303 リダイレクトするため、アドレスに token を残しておくのは安全です——そして Cookie が有効であるかぎり、期限切れの token は 401 になりません。どちらも効かないときは、ページがその旨をはっきり伝えます。

**複数の Host**：Cookie 名はオーソリティのハッシュを含むため、複数の Host のセッションは 1 つの WebKit データストアに共存します。Host の切り替えは、単なる URL の切り替えです。

## 設定

設定ウインドウ（ツールバーの Host メニュー →「Host を管理…」、または ⌘,）には 2 つのタブがあります。

**Host**——ブックマークの追加・削除・編集：

| フィールド | 意味 |
| --- | --- |
| 名前 | ピッカーに表示される。空の場合はアドレスが使われる |
| アドレス | Host の origin。例：`http://127.0.0.1:3080` |
| 起動 token | `dsh web` の出力の `?token=…`。Cookie を保持していないあいだだけ必要 |
| この Host のローカル dsh を起動 | アプリが子プロセスを生成する |
| profile | 代行起動モードの `--profile`。デフォルトは `web` |
| 追加引数 | `dsh` の呼び出しに追加される。例：`--trusted-host dsh.internal` |
| カスタム起動コマンド | 代行起動モードで呼び出し全体を置き換える。`dsh web: http://…` 行を出力する必要がある |
| dsh 実行ファイルパス | 代行起動モードでどの `dsh` を実行するか。空なら検索（「`dsh` を探す」を参照） |

**一般**——特定の Host ではなくアプリ自身に属する設定：

| フィールド | 意味 |
| --- | --- |
| 言語 | インターフェイス言語：英語（デフォルト）、简体中文、繁體中文、日本語、Français、Deutsch、Español |
| 通知 | 待機中の Host と終了したタスクの macOS 通知。デフォルトで有効 |
| 設定ファイル | 設定がどこに保存されるか。パスが表示され、選択してコピーできる |

ブックマークとその他の設定は、編集するとそのファイルに書き込まれます。書き込み・移行・保護のされ方は、上の「覚えていること」を参照してください。

## 既知の制約

- **プレーン http と ATS**：Host が LAN 上の `http://` であることがあるため、`Resources/Info.plist` は `NSAllowsArbitraryLoadsInWebContent` を設定しています（緩和されるのは WebView コンテンツだけ。アプリ自身のリクエストは ATS のままです）。前に `https://` のリバースプロキシを置けば不要になります。
- **リモート Host はこのクライアントを認めねばならない**：dsh の `/api` にはブラウザ信頼の垣根があり、ループバック、デプロイ由来の LAN IP リテラル、`--trusted-host` で宣言されたオーソリティを受け付けます。ドメイン名でリモート Host に接続するには、その Host を `--trusted-host` 付きで起動する必要があります。また `dsh web` の CLI は `--host 0.0.0.0` を拒否します。マシン外へのサービス提供には、設定層で `host: '0.0.0.0'` が必要です。
- **App Sandbox なし**：代行起動モードは `dsh` を生成しますし、harness のセッションツールはもともとユーザーのマシンでコマンドを実行するため、サンドボックスはその信頼モデルを壊します。外部 Host にしか接続しないなら、自分でサンドボックスと `com.apple.security.network.client` を追加できます。
- **スコープ**：このアプリは会話そのものに機能を追加しません——Web UI にあるものがすべてです。ディスプレイの周りに足すのは、Host ピッカー、通知、言語、そして初回起動ガイドです。
- **前提条件**：Web UI をサーブできる dsh Host。`dsh web` の起動行と `?token=` の交換は 0.1.5-rc.1 から安定しています。

## dsh-for-mac との関係

`dsh-for-mac` はもう一方の道を行きます。通信プロトコルを Swift で再実装する（単項 RPC + `/api/remote.mux` + イベントストリーム）道です。完全にネイティブなインタラクションが得られる代わりに、プロトコルを自分で追跡し、ドリフトを自分で背負います。このプロジェクトは意図的にそれをしません。両者は共存できます。このアプリが実際に足すネイティブな形のもの——通知、言語に追従するメニューバー——は、接続モデルに触れずページを包むだけです。

## 開発

```sh
swift build --disable-sandbox
swift test --disable-sandbox
swift run dsh-bezel --dump-config   # 設定ファイル：そのパス、または中身
swift run dsh-bezel --dump-hosts    # 保存されたブックマークだけ
```

裸の実行ファイルと bundle は 1 つの設定ファイルを共有するため、`swift run` での実験は実際の設定を使います——`BEZEL_CONFIG` が別を指していない限り。DSH harness 配下でのビルドには `--disable-sandbox` が必要です。harness は自身のサンドボックスを入れ子にできないからです。
